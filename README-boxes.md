# build_boxes.py — สร้าง _box_cache.json ให้ครอบคลุมทุกไฟล์

## ปัญหาของเดิม
`_box_cache.json` ถูกสร้างโดยโค้ดที่ฝังอยู่ใน `table_test.py` ซึ่ง
- วนเฉพาะไฟล์ที่อยู่ในไฟล์เฉลย `_truth_blind.csv` จึงได้แค่ 6 หน้า
- ไม่หมุนหน้าที่สแกนกลับหัวหรือตะแคง
- OCR ทุกหน้าแม้หน้านั้นจะมี text layer อยู่แล้ว
- และตอนนี้ `table_test.py` รันไม่ได้แล้ว เพราะ import `find_header_band`,
  `column_spans`, `read_row` ซึ่งถูกถอดออกจาก `tables.py` ไปตั้งแต่เปลี่ยนมาใช้
  วิธีระบุคอลัมน์ด้วยเลขคณิต

## ตัวใหม่
```bash
python scripts/build_boxes.py docs_in/*.pdf          # ทำต่อจากของเดิม ข้ามหน้าที่มีแล้ว
python scripts/build_boxes.py --force docs_in/*.pdf  # อ่านใหม่ทับของเดิม
python scripts/build_boxes.py --ocr-only docs_in/*.pdf
```

- **หน้าที่มี text layer ไม่ต้อง OCR** — ใช้ `pdftotext -bbox-layout` ได้พิกัดจริง
  แม่นกว่า OCR และเร็วกว่ามาก
- **หน้าสแกนหมุนให้ตั้งตรงก่อน** ด้วย OSD ของเทสเซอแรกต์ แล้วค่อย OCR ด้วย RapidOCR
- คีย์ยังเป็นรูปแบบเดิม `<ชื่อไฟล์ไม่มีนามสกุล>/page_001.png` — `table_test2.py` ใช้ได้เหมือนเดิม
- เขียนต่อจาก cache เดิม หน้าที่มีอยู่แล้วจะข้าม

## จุดที่ต้องระวังในการรวมคำเป็นเซลล์
RapidOCR คืนกล่องระดับ "ข้อความหนึ่งช่วง" แต่ `pdftotext` คืนทีละคำ
ถ้าเอาคำมาใช้ตรง ๆ ประโยคใต้ตารางจะแตกเป็นคำ ๆ แล้ว `(8)` จะกลายเป็นเซลล์ตัวเลขลอย
ที่ถูกจัดเข้าคอลัมน์ผิด — ปัญหาเดียวกับที่เคยทำให้คอลัมน์พาเลทหายไปทั้งคอลัมน์

`merge_words()` จึงรวมคำที่อยู่ติดกันบนบรรทัดเดียวกัน เมื่อช่องว่างน้อยกว่า
1.2 เท่าของความสูงตัวอักษร ทำให้ได้เซลล์ที่ใกล้เคียงกับผลของ RapidOCR

## หลังจากนี้
เมื่อ box cache ครอบคลุมทุกหน้าแล้ว ควรให้ `split_docs.py` เลิกใช้ `.page_cache.json`
ของตัวเอง แล้วมาอ่านจาก box cache แทน จะได้ไม่มีกรณีที่หน้าเดียวกันถูกจำแนกคนละอย่าง
เพราะคนละ OCR (เกิดขึ้นแล้วกับ VORETO — `split_docs` ว่า Invoice ส่วน `pl_test` ว่า Packing List)
