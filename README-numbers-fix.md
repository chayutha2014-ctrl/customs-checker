# แก้ `parse_number` — บั๊กสองตัวที่เจอจากการรันกับ Packing List จริง

## บั๊กที่ 1 — อ่านเป็นพันเท่าแบบเงียบ ๆ

```
เดิม  parse_number("22,687.000")  ->  22,687,000.0     ผิด 1000 เท่า
ใหม่  parse_number("22,687.000")  ->  22,687.0         ถูก
```

กฎเดิมคือ "ถ้ามีตัวคั่นหลายตัวและทุกกลุ่มยาว 3 หลัก = ตัวคั่นหลักพัน"
แต่ `22,687.000` มีตัวคั่นสองชนิดปนกัน กลุ่มสุดท้ายคือทศนิยม 3 ตำแหน่ง

**กระทบตรง ๆ กับใบขนไทยและ Packing List ซึ่งใช้ทศนิยม 3 ตำแหน่งเป็นปกติ**
เช่น `1,991.000 KGM` จะถูกอ่านเป็น 1,991,000

แก้เป็น: **ถ้าตัวคั่นเป็นคนละชนิดปนกัน ตัวสุดท้ายคือจุดทศนิยมเสมอ**
กฎ "กลุ่มละ 3 หลัก = หลักพัน" ใช้ได้เฉพาะเมื่อตัวคั่นเป็นชนิดเดียวกันทั้งหมด

| ค่า | เดิม | ใหม่ |
|---|---|---|
| `22,687.000` | 22687000 | **22687.0** |
| `1,991.000` | 1991000 | **1991.0** |
| `1,234,567` | 1234567 | 1234567 |
| `1.234.567` | 1234567 | 1234567 |
| `26.947.32` | 26947.32 | 26947.32 |
| `500.000` | 500.0 | 500.0 |

## บั๊กที่ 2 — ตัวเลขที่มีหน่วยติดกันถูกทิ้งทั้งหมด

```
เดิม  parse_number("27526PCS")     ->  None
      parse_number("16123.02KGS")  ->  None
ใหม่  27526.0  /  16123.02
```

ด่านกันรหัสสินค้า (`\d[A-Za-z]`) ปฏิเสธทิ้งหมด แถวรวมของ Packing List หลายใบเขียนแบบนี้

```
TOTAL 27526PCS 2006CTNS 16123.02KGS 20364.16KGS 158.17CBM
```

ทุกค่าถูกทิ้ง แถวรวมจึงกลายเป็นแถวที่ไม่มีตัวเลข และหาแถวรวมไม่เจอ

แก้โดยยกเว้นเมื่อตัวอักษรท้ายเป็น **หน่วยที่รู้จัก** (PCS, CTNS, KGS, CBM, PLTS, SETS, M3 ...)
รหัสสินค้าอย่าง `C91542`, `80BP0233TB`, `2605B` ยังถูกปฏิเสธเหมือนเดิม

# ทางที่ 2 ของตัวอ่าน Packing List — ใบที่ไม่มีแถวรวมในตาราง

พบจริงที่ `Scan2026-09-03_181503` หน้า 4 — ตารางมีแต่บรรทัดสินค้า
ยอดรวมเขียนเป็นข้อความใต้ตารางล้วน ๆ

```
TOTALPCS 150 PCS      TOTALCTNS 4 CTNS
TOTAL N.W. 20.50 KGS  TOTALCBM 0.200 CBM
```

`find_total_row()` หาไม่เจอเพราะไม่มีแถวรวมให้หา
เพิ่มทางที่ 2: **บวกทุกค่าในแต่ละคอลัมน์ แล้วเทียบกับยอดที่เขียนเป็นข้อความ**
ต้องตรงกันอย่างน้อย 2 คอลัมน์จึงยืนยัน (เกณฑ์เดียวกับทางที่ 1)
